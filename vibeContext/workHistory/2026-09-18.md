## 팀 확인이 필요하다고 명시된 미결 사항 (§5/§6)

1. 응답 바디를 저장하지 않는 기존 §16 원칙과, 스키마 검증을 위해 바디를 봐야 하는
   이번 기능이 정면 충돌 — 절충안(성공 시 필드명/타입만, 실패 시만 마스킹된 값 일부)
   채택 여부 미확정.
2. 쓰기 메서드 직접 호출을 1단계에서 GET/HEAD로만 한정할지.
3. 프로그램 범위 매핑(안 A, 캐시 기반)은 "베이스라인 전체 탐색"이 이미 있어야
   동작한다 — 캐시 없을 때 자동 전체 탐색으로 대체할지, 사용자가 먼저 수동으로
   돌리게 할지 UX 결정 필요.
4. 컨트롤러→엔드포인트 매핑이 Spring 전용(Express/Next.js 라우트 매핑은 기존 한계
   그대로) — 1단계 MVP를 Spring Boot 대상 프로젝트로 한정하는 데 대한 확인 필요.
5. (부가) 명세 없는 사내 API가 흔한지, `manual` 케이스 입력 UI에 얼마나 투자할지.
6. (부가) 비로그인 상태 재호출로 권한 우회를 탐지하는 §1.5-5 보너스 기능을 Phase 17에
   포함할지 별도 Phase로 미룰지.
